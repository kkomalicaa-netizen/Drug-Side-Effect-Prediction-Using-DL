# Drug Side-Effect Prediction

A Flask demonstration application that combines a Keras model and scikit-learn
pipelines to explore drug side-effect predictions. It also includes a
drug-interaction lookup, prediction history, and PDF/Excel report exports.

> **Not for medical use.** This project is an educational prototype, not a
> clinically validated tool. Its bundled dataset is randomly generated, and
> its predictions, interaction warnings, risk estimates, and suggested
> alternatives must not be used to diagnose, treat, or make medication
> decisions. Consult a qualified healthcare professional.

## Requirements

- Python 3.11
- Windows, macOS, or Linux
- About 8 GB RAM recommended

## Run locally

From the project directory:

```shell
python -m venv .venv
```

On Windows, you can instead run `.\run_project.bat`, which creates and uses a
`venv` environment and installs the dependencies.

Activate the environment, then install dependencies:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

```shell
# macOS/Linux
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Open <http://127.0.0.1:5000/>.

The trained model files are included under `model/`. The application creates
the SQLite database under `database/` on startup. If model artifacts need to
be regenerated, run `python train_model.py` from the `model/` directory. The
optional scikit-learn pipelines can be regenerated with `python train_ml.py`
from the project directory.

## Dataset

`dataset/drug_data.csv` is generated by `generate_dataset.py`. The script
assigns side effects randomly and does not model real clinical relationships.
Regenerating the dataset will replace the bundled CSV.

## Privacy and configuration

The local database may contain account details and prediction history. It,
generated reports, logs, virtual environments, and local `.env` files are
excluded from version control. Do not commit real patient information,
credentials, or private datasets.

Flask uses a random session key when `SECRET_KEY` is not set, which means
sessions are invalidated when the app restarts. Set a persistent, randomly
generated `SECRET_KEY` in the environment for stable local sessions. For
deployment, configure a strong secret outside the source code and use a
production WSGI server; do not enable Flask debug mode on a public server.
